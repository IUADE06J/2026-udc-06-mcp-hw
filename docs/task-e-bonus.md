## Шлях 1 — той самий сервер у другому хості

**Хост 1:** Cursor (Task A–B) · **Хост 2:** OpenCode

| | Хост 1 (Cursor) | Хост 2 (OpenCode) |
|---|---|---|
| Файл конфігурації | `.cursor/mcp.json` | `.opencode/opencode.json` |
| Чи знадобилось міняти сам сервер | Ні — `mcp-server/dist/server.js` не змінено | Ні — той самий білд |
| Tools видно | Так — `search_inventory`, `check_stock`, `low_stock` у MCP-сервері `catalog` | Так — ті самі 3 tools з’явились в агенті |
| Resource видно | Так — `inventory://catalog` (читається в Cursor) | Так — `inventory://catalog` (Catalog summary) |
| Той самий промпт → та сама поведінка? | Так — «знайди товари найменшої кількості» → прямий виклик `low_stock` | Не зовсім: агент обрав `search_inventory` з порожнім запитом, отримав увесь каталог (24 SKU) і сам звів топ-5 за залишком |

Обидва хости на промпт вище дали узгоджений результат, але різними шляхами:

- **Cursor** — прямий виклик `low_stock`: повний список 9 SKU нижче reorder-рівня,
  найменший stock першим: `DK-4001`, `WC-8002`, `DS-6002`, `MS-2001`, `MN-3002`,
  `HS-5002`, `SS-1102`, `KB-1002`, `CB-7003`.
- **OpenCode** — виклик `search_inventory("")` → весь каталог → власне зведення
  топ-5 за stock: DK-4001 (0), WC-8002 (1), DS-6002 (2), MS-2001 (3), MN-3002 (4),
  всі позначені як needsReorder. Підмножина того ж списку `low_stock` —
  фінальні дані збігаються, відрізняється лише обраний tool і форма відповіді.

(Це не промпт Task D; для крос-хоста достатньо одного й того самого запиту на обох.)

**Що довелося адаптувати:** лише формат конфіга, сам сервер не чіпався:

- `"type": "stdio"` (Cursor) → `"type": "local"` (OpenCode);
- окремі поля `command` + `args` → один масив `command`;
- `${workspaceFolder}` OpenCode не підставляє → замінено на відносні шляхи
  (`./app/data`, `./mcp-server/dist/server.js`) від кореня проєкту;
- додано `$schema: "https://opencode.ai/config.json"` для валідації.

Див. `.cursor/mcp.json` та `.opencode/opencode.json`.

**Висновок:** сервер справді портативний — це звичайний stdio-процес, який
говорить протоколом MCP і нічого не знає про хост. Непортативним є лише
*конфіг*: кожен хост має власний формат запису й власне місце файлу
(`.cursor/mcp.json` vs `.opencode/opencode.json`), тому підключення до другого
хоста — це завжди невеликий ручний переклад конфігу, а не «увімкнув і працює».
Нюанс: «та сама поведінка» стосується даних сервера (вони ідентичні), але вибір
tool — рішення агента хоста, тож різні хости можуть розв'язувати той самий
промпт різними tools (`low_stock` vs `search_inventory` + власне зведення).
